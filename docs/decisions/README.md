# Decisiones y continuidad

## Portable project context (agent-kit)

- At the start of meaningful work in a Git project, read `docs/agent-context.md`, the newest `docs/handoff.md` entry and relevant `docs/decisions/*.md` if present. Check the current branch/worktree and actual files: notes are context, not authority to override the user or evidence that code/tests are still current.
- The user authorizes keeping these Markdown notes automatically, without asking each time. If missing, run `agent context init` in the CURRENT project only. This adds a small managed pointer to AGENTS.md/CLAUDE.md and creates context docs without installing the full kit template. Do not scan/initialize other repos. If the user asks for no file changes or the workspace is read-only, respect that and return a proposed checkpoint instead.
- At each completed milestone, before the final answer, before an intentional handoff/compaction, and when blocked after meaningful work, save a compact checkpoint using one standalone command with simple quoted options: `agent context save --objective "Goal" --summary "Current state" --next "Next step"`. Add `--done "Completed item"`, `--pending "Open issue"`, `--check "command" passed|failed|not_run "Evidence"`, and `--decision "Title" accepted|proposed "Reason" "Basis of approval or proposal"` as needed; repeat options for multiple items. Use these options, NOT JSON, shell pipelines or compound commands. The CLI also accepts JSON for scripts, but that format is not recommended for agent shell calls.
- Save only actual work and decisions, not every greeting or speculative example. Use Spanish, exact relative paths and enough context for another tool to continue. Include unresolved questions, failures and tests NOT run. Never turn a suggestion into approval, or infer a successful test from a worker's claim. New decisions append; do not silently rewrite prior decisions. Reuse existing decisions instead of duplicating them.
- Never put credentials, tokens, .env contents, personal/customer/research data, full transcripts, large tool output or private URLs in context. Summarize minimally. These docs may be committed/shared with the repo; verify their content first. No automatic commit/push or upload is authorized by context saving.
- A delegated worker returns its checkpoint to its coordinator and does NOT initialize/save shared context or create other agents. The coordinator is the single context writer and consolidates verified worker results; no extra model call is needed to summarize.
- `agent context save` updates `docs/agent-context.md`, appends a dated entry to `docs/handoff.md`, and writes new decision records in `docs/decisions/`. Existing handoff content is preserved. It does not save full conversations. Reopen this project in Codex/Claude Code and read these files to resume; no chat synchronization is implied.
- If saving fails, report the failure and provide the checkpoint in the response rather than claiming it was saved. If the CLI is unavailable, read existing notes and propose/install the minimal context helper; do not download tools automatically. A forced exit/crash can lose work since the last checkpoint, so save meaningful intermediate milestones.
